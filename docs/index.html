New · System Viewer

Open a block design without opening Vivado.

A read-only diagram of a Vivado block design or a Platform Designer system. Files are read as text and never executed, so it needs no vendor tool and no license, and it works offline.

Press CtrlShiftV on any supported file

.tcl Vivado block design Script written by write_bd_tcl
.qsys Platform Designer system Nested subsystems open as levels
.tcl Platform Designer script System script for qsys-script

Clock and reset domains, on the wire

Every clock and reset net is drawn as a routed tree. Turn on domain colors to read frequencies at the pins and see where a signal crosses from one clock to another.

2 CDC · 2 RDC FCLK_CLK0 · 100 MHz

Walk the hierarchy

Double-click a block to enter it, or expand it in place as a frame with its pins on the border. Breadcrumbs and the mouse back button take you up.

Find unconnected pins

One toggle dims everything without findings and lists every open pin with a link to the line that created it.

undriven unused

Knows your workspace

Definitions in your .ip.yml and HDL files fill in pins, directions, and interface types, with a link to where each block is defined. Blocks defined elsewhere stay visible as black boxes.

Address map, clocks, and resets in one panel

The bottom panel lists every address segment, clock domain, reset source, and unconnected pin of the design. Select a row to jump to its instance; follow the source link to the exact line.

Isolate what matters

From a crowded level to the few blocks you care about, in one right-click.

Diagrams for your documentation

Export the current view as SVG, PNG, or JPG, or render from the command line. The same command always gives the same file, so committed images change only when the design does.

# light or dark, with or without grid and legend
$ ipcraft render design.tcl --out image.svg
$ ipcraft render design.tcl --out image.png --scale 2
$

Visual editors

A dedicated editor for each part of the specification.

01 · .ip.yml

Design an IP core on a visual canvas.

Place clocks, resets, ports, bus interfaces, and parameters. Select an item to edit its properties in the inspector.

Explore the IP Core editor →
02 · .mm.yml

Define registers and bit fields visually.

Edit blocks, registers, and bit fields in keyboard-friendly tables with a bit layout that stays synchronized with the YAML.

Learn memory-mapped registers →
03 · captured data

Inspect captured data against register definitions.

Map CSV captures and literals onto real register definitions, then wire operators together to decode, combine, and transform values.

Workflow

From specification to implementation, described once.

  1. 1

    Describe

    Define ports, interfaces, address blocks, registers, and fields in visual editors. Every change stays visible in reviewable YAML.

  2. 2

    Generate

    Generate VHDL or SystemVerilog, bus wrappers, register files, cocotb tests, documentation, and vendor project files.

  3. 3

    Verify and build

    Check the generated HDL, run simulations, inspect captured data, and build with Vivado or Quartus without leaving VS Code.

Capabilities

The repetitive work between formats and tools, automated.

0x00

Vendor project generation

Complete RTL projects with bus wrappers, constraints, packaging metadata, testbenches, and scripts for Vivado or Quartus.

0x04

Consistency checks

Cross-check the specification, the top-level HDL, and the vendor artifacts to catch mismatches before integration. Read the guide

0x08

Import existing designs

Turn VHDL entities, Platform Designer _hw.tcl components, and Vivado component.xml metadata into an IPCraft specification instead of starting from a blank file.

0x0C

Bring your own templates

A scaffold pack is a plain directory of Nunjucks templates that overrides any built-in template by file name. Replace one file or the entire set. Read the guide

0x10

Readable, version-controlled YAML

Compact YAML stays at the center. Visual edits preserve your comments and numeric formatting, so diffs stay reviewable.
